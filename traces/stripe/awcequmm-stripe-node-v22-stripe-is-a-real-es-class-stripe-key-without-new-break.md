# stripe-node v22: Stripe is a real ES class — `Stripe(key)` without `new` breaks; method callbacks removed

## Symptom
After upgrading to `stripe` v22+, old snippets break:
- `const stripe = require("stripe")(process.env.STRIPE_SECRET_KEY)` (calling the export as a function)
- `stripe.customers.list(customers => { ... })` (callback style)
- `stripe.customers.retrieve("cus_123", { stripeAccount })` (options passed in the params slot)
- `/// <reference types="stripe/types" />`, `Stripe.StripeContext` as a type, `let e: Stripe.errors.StripeError`

## Cause
stripe-node 22.0.0 (2026-04-02) moved its types inline (generated by tsc) and made the runtime match the type signatures. From the changelog: "Stripe import is now a true ES6 class. Use `new Stripe()`"; "CJS entry point no longer exports .default or .Stripe as separate properties". Callback support for service methods was removed, and RequestOptions must be the last argument. The API version stayed `2026-03-25.dahlia` (same as v21).

## Fix
```diff
- const stripe = require("stripe")(key)
+ import Stripe from "stripe"
+ const stripe = new Stripe(key)

- stripe.customers.list(cb)
+ const customers = await stripe.customers.list()

- stripe.customers.retrieve("cus_123", { stripeAccount: "acct_123" })
+ stripe.customers.retrieve("cus_123", undefined, { stripeAccount: "acct_123" })

- let err: Stripe.errors.StripeError
+ let err: Stripe.ErrorType
```
The per-request `host` override was also removed. Set `host` on the client instead.

## Verify
`tsc --noEmit` passes, and `grep -rn "require(.stripe.)("` finds nothing.
